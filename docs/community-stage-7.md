# Stage 7: pilot readiness

Completed four-role browser coverage on the local React app backed by the real existing Supabase project: anonymous visitor, author, contributor and a dedicated synthetic moderator. The complete draft/publish/solution/test/accept/close journey passed again, including forbidden contributor draft access and acceptance. The expanded pilot harness passed vote/remove, no self-vote UI, author-only reversal/reacceptance across refresh, private reporting, nonmoderator denial, hide/restore, mobile width and local privacy controls.

Fixed a real login race: profile resolution could lag the login promise and leave an authenticated user on the login page. The auth page now resumes the safe intended route when account state settles; a regression test covers delayed state. Added a keyboard skip link and explicit fictional-example banners to cards/discussions. Simulated solved outcomes use an illustrative heading, never a claim of real equipment verification. The reviewed `20260926000400_community_example_labels.sql` was dry-run and applied; it marks existing labelled fixtures and automatically preserves the marker on future example/test posts. No content was removed.

Privacy-conscious pilot measurement is off by default and entirely on-device. Opt-in counts include submitted searches, newly published problems, submitted solutions and later-day browser returns. No queries, content, identity, fingerprint or network telemetry is stored/sent by this feature. Counts expire after 30 days on the next recorded event and can be deleted by opting out. These are browser counts, not unique-user analytics. `/privacy` explains public/draft/report boundaries, operational logs and manual requests through the pilot organizer.

Monitoring changes disable replay and performance sampling, set sendDefaultPii=false, and allowlist only generated error type and build-owned stack locations. User/request/breadcrumb/extra data and query strings are dropped. Monitoring delivery itself still needs a configured operational project and release smoke test.

Checks: 28 SQL scenarios pass across 26 migrations; frontend tests cover local opt-in/deletion/retention and monitoring redaction alongside the existing journey, moderation and auth suites; TypeScript and production build pass. Real browser tests run through `community-browser-smoke.mjs` and `community-pilot-smoke.mjs`, using ignored dedicated-account credentials. Fixtures stay visibly labelled; no invitations, Azure deployment or domain changes were made. See `pilot-tester-checklist.md` for the short human checklist.

Limits: no physical-device/Safari or assistive-technology certification, operational moderator staffing, real email delivery, or self-service account export/deletion. Browser role tests are synthetic; the three fictional reference cases are not customer validation. Counts are not centrally aggregated; participants may voluntarily share their displayed counts. Keep pilot scope small until the release prerequisites are reviewed.
